# speed-test

Консольный скрипт, который меряет скорость скачивания. Он делает N запросов к указанному адресу **последовательно**, каждый раз дочитывая ответ до конца, а потом считает среднее время запроса, общий объём скачанного и скорость.

Внешних зависимостей нет: используется встроенный в Node.js `fetch`.

## Требования

Node.js 18 или новее. Проверить версию:

```bash
node -v
```

## Запуск

```bash
git clone <ссылка-на-репозиторий>
cd speed-test

node index.js <url> [--count 10] [--timeout 30]
```

Ставить пакеты через `npm install` не нужно.

Пример:

```bash
node index.js https://speed.hetzner.de/100MB.bin --count 5
```

### Параметры

| Параметр | Сокращение | По умолчанию | Описание |
|---|---|---|---|
| `<url>` | — | обязателен | http(s)-адрес, к которому идут запросы. Лучше брать большой файл |
| `--count` | `-n` | `10` | Сколько запросов сделать |
| `--timeout` | `-t` | `30` | Таймаут одного запроса в секундах (включая скачивание тела) |

### Пример вывода

```
Адрес:    https://example.com/big.jpg
Запросов: 10, таймаут: 30 с

[ 1/10] ✓    812 мс    5.24 МБ    51.63 Мбит/с
[ 2/10] ✓    640 мс    5.24 МБ    65.50 Мбит/с
...
[10/10] ✗  30001 мс  таймаут (больше 30 с)

──────── Итог ────────
Успешных запросов:   9 из 10
Скачано всего:       47.16 МБ
Среднее время:       701 мс
Скорость скачивания: 59.79 Мбит/с (7.47 МБ/с)
```

## Единицы измерения

- **Скорость: мегабиты в секунду (Мбит/с, Mbps).** В этих единицах скорость указывают провайдеры и сервисы вроде Speedtest. Рядом в скобках выводятся мегабайты в секунду (МБ/с).
- **Объём: байты с десятичными приставками.** 1 КБ = 1000 байт, 1 МБ = 1 000 000 байт (это MB, а не MiB = 1 048 576).
- 1 Мбит = 1 000 000 бит, 1 байт = 8 бит.
- **Время: миллисекунды.**

## Как считается результат

- **Время запроса** — от отправки запроса до момента, когда **последний байт тела** прочитан. Важно, что `await fetch()` завершается уже на заголовках, поэтому таймер останавливается только после полного чтения тела.
- **Объём** — реально полученные байты: тело читается потоком, размеры кусков складываются. На заголовок `Content-Length` скрипт не опирается, потому что его может не быть (chunked-ответ), а при сжатии он показывает не тот размер. Файл целиком в память не загружается.
- **Скорость** — `все скачанные байты / суммарное время успешных запросов`. Это не среднее арифметическое скоростей отдельных запросов: такое среднее завышается быстрыми запросами.
- **Среднее время** — суммарное время успешных запросов, делённое на их количество.

## Обработка ошибок

- Неверный адрес, неизвестный флаг или некорректное число → понятное сообщение, код выхода `1`.
- Ответ со статусом не 2xx (404, 500 …), сетевая ошибка, таймаут → запрос помечается как неудачный (`✗`), скрипт **продолжает работу**. В статистику неудачные запросы не входят.
- Если неудачными оказались все запросы → скорость не считается, код выхода `1`.

## Защита от кэша

К каждому запросу добавляется уникальный параметр `?_nocache=...` и заголовок `Cache-Control: no-cache`. Иначе CDN или прокси могли бы отдать сохранённую копию, и замер оказался бы нечестным.

## Ограничения

- Первый запрос обычно медленнее остальных, потому что в него входит установка соединения (DNS, TCP, TLS). Следующие запросы идут по уже открытому соединению (keep-alive).
- Результат зависит от сервера: если он сам отдаёт данные медленно, скрипт покажет скорость сервера, а не вашего канала.
